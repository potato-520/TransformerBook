2.3 多头注意力机制 (Multi-Head Attention, MHA)

本节核心认知目标：
理解为什么单个 Attention 不够用，掌握多头注意力（MHA）的“特征子空间多路复用”思想，彻底吃透张量维度的切分（Split）、并行计算与合并重组（Concat & Projection）流水线。

1. 📜 科学史话：三幕剧（背景、危机与大师破局）

🎬 第一幕 · 时代背景：单头注意力（Single-Head）的初级尝试

最初，研究人员尝试在整整 4096 维的庞大特征空间上直接运行单一的缩放点积注意力，希望用这一个大矩阵把所有词间关系一网打尽。

💥 第二幕 · 遭遇危机：多重语境关系的“平均化坍塌”

然而，自然语言中的语境关系是极其错综复杂的多维网络：
- Head 1 关注语法依赖：例如主谓宾搭配（"The cat" 关注动词 "sat"）；
- Head 2 关注代词指代：例如代词 "it" 锁定名词 "animal"；
- Head 3 关注时空状语：例如时间与地点伴随关系。
如果只用单个注意力头，Softmax 会强行把这几种完全不同维度的模式混合求平均，导致模型顾此失彼，特征表达被严重稀释钝化！

💡 第三幕 · 大师破局：诺姆·沙泽尔（Noam Shazeer）与特征子空间多路复用

Google 天才研究员诺姆·沙泽尔（Noam Shazeer）提出了极具启发性的 Multi-Head Attention（多头注意力机制）：
“不要在一个 4096 维的大空间里单打独斗，而是把它切分成 32 个独立的 128 维低维子空间！”
每个子空间（每个 Head）就像一位佩戴不同滤镜的专业侦探，互不干扰地并行捕捉特定维度的语义模式，最后再通过拼接（Concat）与线性投影 $W_O$ 完美重组！
更绝妙的是：总计算量（FLOPs）与单头完全一模一样，但模型的表征抽取能力提升了数十倍！

2. Tensor Shape 全链路流转轨迹

张量变形记（Tensor Reshape Pipeline）：
1. 输入张量 $X$：[B, L, D] (例如 Batch=2, SeqLen=512, Dim=4096)
2. 线性投影 QKV 并分头转置：[B, H, L, d_k] (Head=32, $d_k=128$)
3. 并行多头 Attention：$Q \times K^T \implies$ [B, H, L, L] $\times V \implies$ [B, H, L, d_k]
4. 多头拼接（Concat）：转置回 [B, L, H \cdot d_k] = [B, L, D]
5. 最终输出投影 $W_O$：[B, L, D] $\times [D, D] \implies$ [B, L, D]

4. Python / NumPy 极简多头注意力实现

import numpy as np

class MultiHeadAttention:
    def __init__(self, d_model=4096, n_heads=32):
        self.d_model = d_model
        self.n_heads = n_heads
        self.d_k = d_model // n_heads
        
        self.W_q = np.random.randn(d_model, d_model) * 0.02
        self.W_k = np.random.randn(d_model, d_model) * 0.02
        self.W_v = np.random.randn(d_model, d_model) * 0.02
        self.W_o = np.random.randn(d_model, d_model) * 0.02

    def forward(self, x):
        B, L, D = x.shape
        q = np.dot(x, self.W_q).reshape(B, L, self.n_heads, self.d_k).transpose(0, 2, 1, 3)
        k = np.dot(x, self.W_k).reshape(B, L, self.n_heads, self.d_k).transpose(0, 2, 1, 3)
        v = np.dot(x, self.W_v).reshape(B, L, self.n_heads, self.d_k).transpose(0, 2, 1, 3)
        
        scores = np.matmul(q, k.transpose(0, 1, 3, 2)) / np.sqrt(self.d_k)
        attn = np.exp(scores - np.max(scores, axis=-1, keepdims=True))
        attn = attn / np.sum(attn, axis=-1, keepdims=True)
        
        out_heads = np.matmul(attn, v)
        concat_out = out_heads.transpose(0, 2, 1, 3).reshape(B, L, self.d_model)
        return np.dot(concat_out, self.W_o)

mha = MultiHeadAttention(d_model=64, n_heads=4)
fake_in = np.random.randn(2, 8, 64)
out = mha.forward(fake_in)
print("多头输出张量 Shape:", out.shape)

5. 打开黑盒：真实工程细节 (为什么各头不单独建矩阵？)

内存连续性与 Strided View：
在 C++ / PyTorch 源码中，分头操作完全不需要进行任何显存数据搬运（零拷贝）！
它仅仅是通过修改张量的步长（Strides）和视图（View），将连续的 4096 维浮点数组在逻辑上解释为 [32, 128] 的二维矩阵，从而保证了底层 GPU L1/L2 Cache 的极速行连续命中！

6. 动手实验与思考题

思考题：
保持总维度 $D_{model}=4096$ 不变，如果我们将头数 $H$ 从 32 头增加到 64 头（每个头的维度从 128 降到 64），注意力机制的理论计算量（FLOPs）会发生改变吗？
提示：不会改变！因为总计算量始终是 $O(B \cdot L^2 \cdot D_{model})$。但更多的 Head 会带来更丰富的特征子空间抽取能力。
