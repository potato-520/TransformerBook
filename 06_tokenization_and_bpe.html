1.1 Tokenization 与 BPE 算法 (Tokenization & Byte-Pair Encoding)

本节目标：理解计算机是如何将离散的自然语言字符切分成不可再分的“数字凭证（Token ID）”，深入掌握现代大模型标配的 BPE（Byte-Pair Encoding）分词算法与词表构建机制。

1. 它解决什么问题？ (工程师视角黑盒引入)

计算机与神经网络只认识浮点数和矩阵，无法直接处理自然语言字符串（如 "hello world"）。
在传统的字符级（Character-level）编码中，序列长度过长（导致计算复杂度激增）；而在词级（Word-level）编码中，未登录词（OOV, Out-Of-Vocabulary）极易导致词表爆炸。
子词分词器（Subword Tokenizer，如 BPE）通过统计相邻字符对的共现频率，动态合并高频子词，在词表大小（约 32k~128k）与序列长度之间取得了最优工程平衡。

2. 输入与输出 (Tensor Shape & 格式转换)

  • 输入：原始自然语言文本字符串（Python str）。
  • 分词过程：字符串 $\to$ 子词字符串列表 $\to$ 词表查表（Vocabulary Lookup）。
  • 输出：一维整数 ID 数组：Shape: [SeqLen]，数据类型为 int64 / int32。

3. BPE 算法的核心迭代逻辑

BPE (Byte-Pair Encoding) 构建词表 3 步循环：
1. 初始化：将所有训练语料切分成单个字符（包含特殊词尾标记 </w>），初始词表为所有基础字符集合；
2. 统计频次：扫描语料库，统计所有相邻字符对（如 ('e', 'r')）的共现频次；
3. 合并高频对：将出现频率最高的字符对合并为一个新的子词单元（如 'er'），并将其加入词表；
4. 重复迭代：直到达到预设的词表大小（Vocab Size，如 32000）。

5. 极小规模人工计算 (BPE 合并模拟)

初始训练语料（带词频）：
"low </w>": 5, "lowest </w>": 2, "newer </w>": 6, "wider </w>": 3

第 1 次迭代：
统计所有字符对频率：('e', 'r') 在 newer 和 wider 中出现 $6 + 3 = 9$ 次（最高频！）。
$\implies$ 合并 ('e', 'r') $ o$ 'er'，加入新词表。

第 2 次迭代：
统计更新后的字符对：('er', '</w>') 出现 $6 + 3 = 9$ 次。
$\implies$ 合并 ('er', '</w>') $ o$ 'er</w>'，加入新词表。

6. Python / NumPy 极简代码实现

from collections import Counter, defaultdict

def get_stats(vocab):
    pairs = defaultdict(int)
    for word, freq in vocab.items():
        symbols = word.split()
        for i in range(len(symbols) - 1):
            pairs[symbols[i], symbols[i+1]] += freq
    return pairs

def merge_vocab(pair, v_in):
    v_out = {}
    bigram = ' '.join(pair)
    replacement = ''.join(pair)
    for word in v_in:
        w_out = word.replace(bigram, replacement)
        v_out[w_out] = v_in[word]
    return v_out

# 初始微型语料库
vocab = {'l o w ': 5, 'l o w e s t ': 2, 'n e w e r ': 6, 'w i d e r ': 3}

# 执行 3 次 BPE 合并
for i in range(3):
    pairs = get_stats(vocab)
    if not pairs:
        break
    best_pair = max(pairs, key=pairs.get)
    vocab = merge_vocab(best_pair, vocab)
    print(f"Step {i+1} 合并最高频对 {best_pair} -> 新语料状态: {vocab}")

7. 数学原理与物理直觉

为什么大模型几乎全部采用基于字节的 Byte-fallback BPE (如 tiktoken, SentencePiece)？

  • 零 OOV（Out-of-Vocabulary）保证：任何未知的罕见生僻字或 UTF-8 表情包，最终都可以退化为最底层的 256 个基本字节（Byte）表示，系统永远不会因为遇到未知字符而崩溃报 <UNK>！

8. 打开黑盒：真实工程细节 (BPE 带来的 LLM 缺陷)

Tokenization 导致的著名 LLM 盲区：
1. 大模型为什么不擅长数单词中有几个 'r'（如 "strawberry"）？ 因为分词器将 "strawberry" 切分为了 ["straw", "berry"] 两个单一 Token，模型在注意力层根本看不到内部的单个字符！
2. 空格敏感性：" hello"（带前导空格）与 "hello"（无空格）在 GPT 词表中是两个完全不同的 Token ID。

9. 动手实验与思考题

思考题：
如果将词表大小从 32000 扩大到 128000（如 LLaMA-3），对大模型的参数量、推理显存和生成吞吐分别有什么影响？
提示：词表扩大会直接增加 Embedding 层和最后的 LM Head 输出投影矩阵的参数量（$[128000, 4096]$），但单次生成的 Token 数量会变少（信息压缩比更高）。
