1.1 Tokenization 与 BPE 算法 (Tokenization & Byte-Pair Encoding)

本节核心认知目标：
理解计算机如何把人类自然语言字符串切分为数字离散 ID 序列，掌握经典字符级/词级切分的致命缺陷，以及 2015 年现代大模型全面采用的 BPE（Byte-Pair Encoding）子词算法与 UTF-8 字节回退机制。

1. 📜 科学史话：三幕剧（背景、危机与大师破局）

🎬 第一幕 · 时代背景：早期的“字切分”与“词切分”两极分化

在早期自然语言处理（NLP）中，人们处理文本只有两个极端：
1. 按字符切分（Character-level）：把英文切成单个字母（a, b, c...），中文切成单字。优点是词表极小（只有几十个字母），但缺点是序列极长（一句话变成上百个字母），且单个字母完全丢失了语义。
2. 按词语切分（Word-level）：用空格或分词词典切出完整单词（如 "apple", "running"）。

💥 第二幕 · 遭遇危机：词表爆炸与致命的 <unk> 未知词黑洞

按词切分在现实工业界很快撞上了灾难：
自然语言是不断演化的，存在海量的时态变化（run, running, ran）、复合词（unbelievable）和网络新词（ChatGPT）。
词表动辄膨胀到几百万，直接撑爆 GPU 显存！
更致命的是：任何词表中没有收录的新词，都会被粗暴替换为 <unk>（Unknown）。当输入一句包含生僻词的句子时，模型满眼都是 <unk>，瞬间“致盲”失去理解能力！

💡 第三幕 · 大师破局：2015 年森里奇（Sennrich）与压缩算法的跨界奇迹

2015 年，爱丁堡大学的学者里科·森里奇（Rico Sennrich）在研究机器翻译时灵光乍现：
“既然 1994 年 Philip Gage 发明的数据压缩算法 BPE（Byte-Pair Encoding，字节对编码） 能通过统计高频字符对把重复数据压缩，我们为什么不能把它拿来切分语言？”
BPE 算法带来了完美的平衡：
1. 高频词整词保留：如 "the"、"is"、"apple" 作为独立 Token；
2. 罕见词自动拆分子词（Subwords）：如 "unbelievable" 自动拆为 ["un", "believ", "able"]！词根的语义被完整保留，彻底终结了 <unk> 灾难，成为 GPT-4、LLaMA-3 等现代大模型的绝对基石！

2. BPE 算法核心构建流程

BPE 词表构建（Training Tokenizer）三步法：
1. 初始化基础词表：将语料库中的所有词全部拆散为单个字符（如 l, o, w, e, r）；
2. 统计最高频相邻对：统计全文中出现频率最高的一对连续字符（例如 ('e', 'r') 出现了 5000 次）；
3. 迭代合并（Merge）：将 ('e', 'r') 融合成一个全新 Token "er" 加入词表。重复这一过程（例如迭代 32,000 次），直到词表达到预定大小！

4. Python / NumPy 极简 BPE 合并循环实现

from collections import Counter

def get_stats(vocab):
    pairs = Counter()
    for word, freq in vocab.items():
        symbols = word.split()
        for i in range(len(symbols) - 1):
            pairs[symbols[i], symbols[i + 1]] += freq
    return pairs

def merge_vocab(pair, v_in):
    v_out = {}
    bigram = ' '.join(pair)
    replacement = ''.join(pair)
    for word in v_in:
        w_out = word.replace(bigram, replacement)
        v_out[w_out] = v_in[word]
    return v_out

# 模拟初始拆解语料
corpus_vocab = {'l o w ': 5, 'l o w e r ': 2, 'n e w e s t ': 6}
print("初始语料词表:", corpus_vocab)

# 进行 3 轮合并
for i in range(3):
    pairs = get_stats(corpus_vocab)
    best_pair = max(pairs, key=pairs.get)
    corpus_vocab = merge_vocab(best_pair, corpus_vocab)
    print(f"Step {i+1}: 合并最高频对 {best_pair} ->", corpus_vocab)

5. 打开黑盒：真实工程细节 (Byte-level Fallback)

为什么现代 Tokenizer（如 tiktoken）连生僻 Emoji 也能分词？
GPT-4 和 LLaMA 采用 Byte-level BPE：基础词表不再由字符构成，而是直接从 256 个原生 UTF-8 字节（0x00 ~ 0xFF） 开始！
即使遇到从未见过的特殊符号或古埃及象形文字，它也能无损退化为 3~4 个 UTF-8 字节对应的 Token，真正做到了 0 丢字、0 异常崩溃！

6. 动手实验与思考题

思考题：
为什么许多大模型在处理中文和代码时，生成的 Token 数量通常比英文多得多（消耗更多费用）？
提示：因为早期很多西方主导的大模型在训练 BPE 词表时，英文语料占比超过 90%，分配给中文的合并规则极少，导致一个常用汉字经常被拆散成 2~3 个独立的字节 Token！
