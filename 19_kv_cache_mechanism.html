4.3 KV Cache 机制与显存加速 (KV Cache & Memory Scaling)

本节核心认知目标：
深入剖析大模型推理中的“第一核心性能生命线”——KV Cache，理解 Prefill（首字填充）与 Decode（自回归解码）两个截然不同的计算阶段，掌握显存容量精确计算公式。

1. 📜 科学史话：三幕剧（背景、危机与大师破局）

🎬 第一幕 · 时代背景：朴素自回归的 $O(L^2)$ 计算泥潭

在最初运行 GPT 推理时，当模型要生成第 500 个词时，系统将前面 499 个词重新完整送入 32 层 Transformer 算一遍。
生成第 501 个词时，又把前 500 个词完整重算一遍……

💥 第二幕 · 遭遇危机：长文本生成的“蜗牛爬行”与显存碎片雪崩

这种重复计算导致每生成 1 个字的耗时随着句子长度呈二次方 $O(L^2)$ 暴涨！在长文本对话中，打字机吐字速度越来越慢直至彻底卡死。
更致命的是：早期框架为每个并发请求预先分配最大显存空间，导致显存内部碎片高达 70%，昂贵的 A100 显卡只能并发服务可怜的几个用户！

💡 第三幕 · 大师破局：KV Cache 与伯克利 PagedAttention 操作系统级革命

工程师们发现了一个神圣的不变量：由于因果掩码的存在，前面已经生成过的历史 Token 的 Key 和 Value 向量是永远恒定不变的！
- KV Cache 破局：把历史的 Key 和 Value 直接持久化在显存中，每生成一个新词只需单步追加 1 个新槽位，推理复杂度瞬间降为 $O(L)$！
- PagedAttention 革命（vLLM）：2023 年，UC 伯克利团队的 Woosuk Kwon 借鉴 Linux 虚拟内存分页机制，将 KV Cache 切分为固定物理页按需分配，将显存浪费率从 70% 骤降至 4% 以下，并发吞吐量飙升整整 4 倍！

3. 工业级 KV Cache 显存容量精确计算公式

显存占用公式：
$$\text{KV Cache Size} = 2 \times \text{Layers} \times \text{Heads}_{kv} \times d_k \times \text{SeqLen} \times \text{BytesPerElem} \times \text{BatchSize}$$ 实战（LLaMA-3 8B, 32层, 8个KV头, FP16）：单个请求在 8k 上下文下仅 KV 缓存就需要约 1.0 GB 显存！
