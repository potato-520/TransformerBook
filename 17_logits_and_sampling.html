4.1 Logits 映射与采样策略 (Logits, Softmax & Sampling)

本节目标：理解大模型是如何将最后一层 Block 输出的抽象隐藏状态（Hidden State）映射回包含数万个词的词表分布，掌握 Temperature、Top-k、Top-p（核采样）的数学机理与工程实现。

1. 它解决什么问题？ (工程师视角黑盒引入)

经过数十层 Transformer Block 提炼后，最后一个 Token 的输出向量 $h_{last} \in \mathbb{R}^{D_{model}}$ 凝聚了前文所有的上下文语义。
但它依然只是一个 4096 维的浮点向量。我们如何从中“挑选出具体的下一个单词”？
这需要两步： 1. LM Head（语言模型头）投影：将 4096 维向量投影为长度为词表大小（如 32000）的未归一化打分向量（Logits）； 2. 采样策略（Sampler）：通过 Temperature 与截断算法从概率分布中抽取下一个 Token ID。

2. 采样核心算法三剑客

采样控制数学原理：
  • Temperature $T$（温度系数）： $$P_i = \frac{e^{z_i / T}}{\sum_j e^{z_j / T}}$$ $T \to 0$ 时退化为贪婪选择（Argmax，确定性最高、最严谨）；$T > 1$ 时拉平概率分布（多样性与创造力激增）。
  • Top-k 采样：仅保留概率最高的 $K$ 个词（如 $K=50$），其余词概率归零并重新归一化。
  • Top-p 采样 (Nucleus 采样)：按概率从大到小累加，保留累积概率刚刚达到阈值 $p$（如 $p=0.9$）的最小集合，能根据上下文动态调整候选词池大小。

4. Python / NumPy 工业级采样器实现

import numpy as np

def sample_next_token(logits: np.ndarray, temperature=0.7, top_p=0.9) -> int:
    # 1. 应用温度系数
    if temperature > 0:
        logits = logits / temperature
    else:
        return int(np.argmax(logits))
    
    # 2. 计算 Softmax 概率分布
    probs = np.exp(logits - np.max(logits))
    probs = probs / np.sum(probs)
    
    # 3. Top-p (Nucleus) 截断
    sorted_indices = np.argsort(probs)[::-1]
    sorted_probs = probs[sorted_indices]
    cumulative_probs = np.cumsum(sorted_probs)
    
    cutoff_index = np.searchsorted(cumulative_probs, top_p)
    valid_indices = sorted_indices[:cutoff_index + 1]
    valid_probs = probs[valid_indices]
    valid_probs = valid_probs / np.sum(valid_probs)
    
    # 4. 多项式分布加权随机采样
    sampled_token_id = np.random.choice(valid_indices, p=valid_probs)
    return int(sampled_token_id)

test_logits = np.array([4.5, 3.2, 1.8, 0.5, -1.0])
next_id = sample_next_token(test_logits, temperature=0.7, top_p=0.9)
print("采样出的 Next Token ID:", next_id)

5. 打开黑盒：真实工程细节 (Repetition Penalty 重复惩罚)

为什么大模型有时会陷入无限车轱辘话循环？
当模型连续生成了相同的词时，这些词的自注意力点积会异常升高，导致后续 Logits 偏高，从而锁死在死循环中。
在推理引擎中，通常会引入 Repetition Penalty（重复惩罚，如 1.15）：如果某个 Token 在过去 64 步中出现过，将其对应的 Logit 强制除以该惩罚因子，有效打破重复怪圈！

思考题：
在编写 Python 代码或进行数学解题（如写一段 C++ 驱动或算微积分）时，应该将 Temperature 设为高（如 1.2）还是设为 0？为什么？
提示：应该设为 0（贪婪选择）。代码与数学属于确定性逻辑，容错率极低，不需要“天马行空的随机创造力”。
