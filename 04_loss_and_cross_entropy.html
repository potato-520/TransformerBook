0.4 Loss 测量尺与交叉熵 (Loss Function & Cross Entropy)

本节核心认知目标：
理解为什么预测分类任务不能使用均方误差（MSE），掌握信息论中“香农熵”与“交叉熵（Cross-Entropy）”的度量本质，理解为什么预测越错、惩罚呈指数级爆发。

1. 📜 科学史话：三幕剧（背景、危机与大师破局）

🎬 第一幕 · 时代背景：经典的均方误差（MSE）统治早期回归

在统计学和早期机器学习中，人们最熟悉的损失函数是均方误差（MSE）： $$\text{Loss} = \frac{1}{2} (y - \hat{y})^2$$ 对于预测房价、温度等连续数值的回归任务，MSE 完美匹配最小二乘法，一度被视为所有机器学习任务的标准答案。

💥 第二幕 · 遭遇危机：分类任务中“错得离谱却拒绝纠错”的死锁

然而，当人们将 MSE 直接套用到配合 Sigmoid/Softmax 的多分类任务时，出现了一个致命 Bug：
假设真实标签是猫（$y=1$），但模型以 **99.9% 的极大置信度误判为狗**（$\hat{y} \approx 0.001$）。
按常理，模型犯了极其严重的原则性错误，理应施加巨大的梯度推力狠狠纠偏！
但求导计算表明：由于 Sigmoid 在饱和区导数 $\sigma'(z) \approx 0$，两项相乘后梯度反而趋近于零！模型陷入“盲目自信的死锁区”，参数完全不更新。

💡 第三幕 · 大师破局：香农信息论与对数似然的绝妙反击

学者们将信息论之父克劳德·香农（Claude Shannon）的“信息熵”思想引入了机器学习，提出了交叉熵损失（Cross-Entropy Loss）： $$\text{Loss} = -\ln(P_{\text{true}})$$ 它带来了两大奇迹：
1. 对数爆炸惩罚：当模型以 99% 的自信犯错时，$-\ln(0.01) \approx 4.60$，损失急剧飙升；当概率逼近 0 时，损失趋于正无穷大！
2. 梯度完美抵消：与 Softmax 结合求导后，复杂的导数项被神奇地化简为极其朴素的残差差值：$\frac{\partial \text{Loss}}{\partial z_i} = P_i - Y_i$！计算速度极快且永不死锁！

2. 交叉熵损失数学机理

核心公式： $$\mathcal{L}_{CE} = - \sum_{k=1}^K y_k \log(\hat{y}_k) = - \log(\hat{y}_{\text{target}})$$ 其中 $\hat{y}_{\text{target}}$ 是模型在真实正确类别上的预测概率。
  • 若真实类别预测概率 $\hat{y} = 1.0$（完美预测）$\implies \text{Loss} = -\log(1.0) = \mathbf{0.000}$；
  • 若真实类别预测概率 $\hat{y} = 0.5$ $\implies \text{Loss} = -\log(0.5) \approx \mathbf{0.693}$；
  • 若真实类别预测概率 $\hat{y} = 0.01$（严重错判）$\implies \text{Loss} = -\log(0.01) \approx \mathbf{4.605}$；
  • 若真实类别预测概率 $\hat{y} \to 0$ $\implies \text{Loss} \to +\infty$（严厉惩罚！）。

4. Python / NumPy 极简交叉熵计算

import numpy as np

def cross_entropy_loss(logits: np.ndarray, target_idx: int):
    shifted_logits = logits - np.max(logits)
    probs = np.exp(shifted_logits) / np.sum(np.exp(shifted_logits))
    loss = -np.log(probs[target_idx] + 1e-12)
    return loss, probs

test_logits = np.array([2.0, 1.0, 0.1])
loss_val, p_dist = cross_entropy_loss(test_logits, target_idx=0)
print("Softmax 概率分布:", np.round(p_dist, 3))
print("交叉熵损失 Loss:", round(loss_val, 4))

5. 打开黑盒：真实工程细节 (LogSumExp 技巧)

数值稳定性（Numerical Stability）：
直接计算 $e^{z_i}$ 极易在 $z_i > 88$（float32 上限）时发生浮点上溢（Overflow）导致 NaN。
PyTorch 的 nn.CrossEntropyLoss 在 CUDA 底层直接实现了 Log-Softmax 融合算子，利用 $\log(\sum e^{x_i}) = M + \log(\sum e^{x_i - M})$（其中 $M = \max(x_i)$），彻底杜绝了溢出隐患！

思考题：
